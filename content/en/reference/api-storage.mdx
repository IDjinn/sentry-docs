# API — `sentry-storage`

[`sentry-storage`](https://github.com/IDjinn/sentry/blob/main/crates/sentry-storage/src/lib.rs#L1) is Sentry's Postgres persistence: pool, embedded migrations and typed repositories (events, incidents, ip_state, rules, routes, datasets) used by the daemon, the CLI and the dashboard. Every query uses runtime `sqlx::query()`, so the crate compiles without a live `DATABASE_URL`. Declares `#![forbid(unsafe_code)]`.

## Pool — module `pool`

### PgPool

```rust
pub struct PgPool { /* sqlx::PgPool */ }
pub async fn connect(cfg: &PostgresConfig) -> Result<Self>;
pub fn connect_lazy(url: &str) -> Result<Self>;
pub async fn listen(&self, channel: &str) -> Result<sqlx::postgres::PgListener>;
pub async fn notify(&self, channel: &str) -> Result<()>;
```

[`PgPool`](https://github.com/IDjinn/sentry/blob/main/crates/sentry-storage/src/pool.rs#L9) honors `max_connections` and `acquire_timeout_secs` from `[storage.postgres]`; [`connect_lazy`](https://github.com/IDjinn/sentry/blob/main/crates/sentry-storage/src/pool.rs#L34) defers connecting (tooling/tests). [`listen`](https://github.com/IDjinn/sentry/blob/main/crates/sentry-storage/src/pool.rs#L52) uses a dedicated connection outside the pool — a LISTEN may block indefinitely without starving the pool. Errors live in [`StorageError`](https://github.com/IDjinn/sentry/blob/main/crates/sentry-storage/src/pool.rs#L76) (`Config`/`Connect`/`Query`/`Migrate`).

## Repositories — module `repo`

### Repo

[`Repo`](https://github.com/IDjinn/sentry/blob/main/crates/sentry-storage/src/repo.rs#L22) holds the pool and lends the repos: [`events()`](https://github.com/IDjinn/sentry/blob/main/crates/sentry-storage/src/repo.rs#L38), [`incidents()`](https://github.com/IDjinn/sentry/blob/main/crates/sentry-storage/src/repo.rs#L45), [`ip_state()`](https://github.com/IDjinn/sentry/blob/main/crates/sentry-storage/src/repo.rs#L52), [`rules()`](https://github.com/IDjinn/sentry/blob/main/crates/sentry-storage/src/repo.rs#L59), [`routes()`](https://github.com/IDjinn/sentry/blob/main/crates/sentry-storage/src/repo.rs#L66), [`datasets()`](https://github.com/IDjinn/sentry/blob/main/crates/sentry-storage/src/repo.rs#L73). Every IP-taking method canonicalizes the address ([`Event::canonical_ip`](https://github.com/IDjinn/sentry/blob/main/crates/sentry-core/src/event.rs#L243)).

### EventRepo

Repository for the `events` table ([`EventRepo`](https://github.com/IDjinn/sentry/blob/main/crates/sentry-storage/src/repo.rs#L84)).

**Writes and cross-node dedupe:**

```rust
pub async fn insert_with_hash(&self, evt: &Event, risk_score: u8, risk_level: RiskLevel,
    verdict: Verdict, signals: &serde_json::Value, payload_hash: Option<i64>, process_us: Option<u64>) -> Result<()>;
pub async fn insert_batch_with_hash(&self, rows: &[EventInsert]) -> Result<()>;
```

[`insert_with_hash`](https://github.com/IDjinn/sentry/blob/main/crates/sentry-storage/src/repo.rs#L223) performs a conditional INSERT: when `payload_hash` was already persisted by a sibling node within the dedupe window (10 s), the row is skipped — the local LRU cannot see other nodes' events (F4.7). [`insert_batch_with_hash`](https://github.com/IDjinn/sentry/blob/main/crates/sentry-storage/src/repo.rs#L339) is the overload-response batch persistence lane (one multi-INSERT per batch). [`EventInsert::from_event`](https://github.com/IDjinn/sentry/blob/main/crates/sentry-storage/src/repo.rs#L134) builds the row; a protocol that fails to serialize becomes JSON `null` — batching never loses an event over one bad payload.

### DatasetRepo

Repository for DB-backed datasets (F7.7, [`DatasetRepo`](https://github.com/IDjinn/sentry/blob/main/crates/sentry-storage/src/repo.rs#L1230)) — curated `user_agent`/`path`/`ja3` lists that become synthetic `feed:<name>` rules and feed the dynamic prefilter:

```rust
pub async fn upsert(&self, name: &str, kind: &str, source_url: Option<&str>,
    action: &str, entries: &[String]) -> Result<()>;
pub async fn list(&self) -> Result<Vec<DatasetRow>>;
pub async fn entries(&self, name: &str) -> Result<Vec<String>>;
pub async fn set_enabled(&self, name: &str, enabled: bool) -> Result<()>;
pub async fn delete(&self, name: &str) -> Result<()>;
```

[`upsert`](https://github.com/IDjinn/sentry/blob/main/crates/sentry-storage/src/repo.rs#L1257) replaces a dataset wholesale in one transaction and fires `pg_notify` on the `sentry_datasets_changed` channel ([constant](https://github.com/IDjinn/sentry/blob/main/crates/sentry-storage/src/repo.rs#L1251)); `set_enabled` and `delete` notify the same way — every node hot-reloads without a restart.

## Dedupe and LISTEN/NOTIFY

**Cross-node dedupe** (F4.7) works like this: every node computes the same `payload_hash` the local LRU uses (IP + method + path for HTTP, raw hash otherwise); the INSERT checks the partial index `events_payload_hash_ts` within the 10 s window and skips duplicates persisted by siblings. The index is partial (`WHERE payload_hash IS NOT NULL`) — events without a hash never pay the lookup.

**Hot-reload** channels via LISTEN/NOTIFY (producers → LISTEN tasks in the daemon):

| Channel | Triggers |
| --- | --- |
| `sentry_rules_changed` | Ruleset recompilation ([daemon](https://github.com/IDjinn/sentry/blob/main/crates/sentry-cli/src/daemon.rs#L2781)) |
| `sentry_datasets_changed` | Dataset re-import into the pipeline and prefilter ([daemon](https://github.com/IDjinn/sentry/blob/main/crates/sentry-cli/src/daemon.rs#L2863); emitted by the `DatasetRepo`) |
| `sentry_blocks_changed` | `BlockTable` re-sync across nodes ([daemon](https://github.com/IDjinn/sentry/blob/main/crates/sentry-cli/src/daemon.rs#L2904)) |
| `sentry_model_changed` | Hot ONNX model swap ([daemon](https://github.com/IDjinn/sentry/blob/main/crates/sentry-cli/src/daemon.rs#L2961)) |

The typical producer is the CLI/dashboard: a Postgres mutation + `NOTIFY` via [`PgPool::notify`](https://github.com/IDjinn/sentry/blob/main/crates/sentry-storage/src/pool.rs#L64). The exception is `sentry_datasets_changed`, emitted inside the [`DatasetRepo`](https://github.com/IDjinn/sentry/blob/main/crates/sentry-storage/src/repo.rs#L1230) itself, in the same transaction as the write.

## Operational notes

- [`EventRepo::insert`](https://github.com/IDjinn/sentry/blob/main/crates/sentry-storage/src/repo.rs#L205) is the single-row wrapper without dedupe (delegates to `insert_with_hash` with `payload_hash = None`) — for low-volume paths; the daemon's hot path uses the batch lane.
- `Repo` is a cheap `Clone` (just the pool handle); so is every lent repo. There is no per-repo state — Postgres is the source of truth, and local caches (`BlockTable`, ruleset) are synced through the channels above.
- The [`error`](https://github.com/IDjinn/sentry/blob/main/crates/sentry-storage/src/error.rs#L3) module re-exports `StorageError`/`Result` defined in `pool.rs`; every query failure becomes `StorageError::Query` with the sqlx error in the text.
