# Command Reference

The CLI is defined with `clap` (derive) in
[`cli.rs`](https://github.com/IDjinn/sentry/blob/main/crates/sentry-cli/src/cli.rs)
and dispatched to the handlers in
[`cmd.rs`](https://github.com/IDjinn/sentry/blob/main/crates/sentry-cli/src/cmd.rs).
Everything below was verified against those definitions.

Conventions: placeholders in backticks (`<ip>`, `<path>`); durations accept
`24h`, `7d`, `30m`. Almost every subcommand loads the config file (and many
require Postgres in `storage.postgres.url`).

## Global flags

| Flag | Description |
| --- | --- |
| `--config <path>` | Config file path. Default: `sentry.toml` in cwd or `/etc/sentry/sentry.toml`. Also via the `SENTRY_CONFIG` env var. |
| `-v` / `-vv` / `-vvv` | Log verbosity: `info`, `debug`, `trace`. |

## Monitor / daemon

### `sentry run`

Starts the daemon in the foreground: sources → pipeline (rules → heuristics →
AI/LLM) → actions, hot-reload via LISTEN/NOTIFY, prune tasks and the
Prometheus metrics server. Handler in
[`daemon.rs`](https://github.com/IDjinn/sentry/blob/main/crates/sentry-cli/src/daemon.rs).

```bash
sentry run
```

### `sentry serve`

Web dashboard (build-step-free SPA) + JSON API in a separate process.
Requires Postgres. Bind and auth come from `[server]`: `host` (default
`127.0.0.1`), `port` (default `8080`),
`auth.mode = "none"|"password"|"token"|"both"` with RBAC (`admin` mutates,
`viewer` is read-only). Handler in
[`server.rs`](https://github.com/IDjinn/sentry/blob/main/crates/sentry-cli/src/server.rs).

Endpoints: `/` (dashboard), `/api/health`, `/api/login`, `/api/logout`,
`/api/me`, `/api/events`, `/api/stats`, `/api/incidents` (+ `/{id}/ack` and
`/{id}/resolve`), `/api/ips/blocked` (+ `/{ip}/block`, `/{ip}/unblock`,
`/{ip}/forgive`).

```bash
sentry serve
```

## Live tail

### `sentry tail`

Live event tail straight from Postgres. Opens the [interactive TUI](tui)
when stdout is a TTY; outside a TTY (or with `--stream`) it prints one line
per event. Implementation in
[`tui/mod.rs`](https://github.com/IDjinn/sentry/blob/main/crates/sentry-cli/src/tui/mod.rs)
and [`tui/stream.rs`](https://github.com/IDjinn/sentry/blob/main/crates/sentry-cli/src/tui/stream.rs).

| Flag | Default | Description |
| --- | --- | --- |
| `--only <levels>` | (all) | Filter by risk level, comma-separated (e.g. `High,Critical`). |
| `--tui` | off | Force fullscreen TUI mode. |
| `--stream` | off | Force non-interactive mode (one line per event). |
| `--theme <t>` | `dark` | Color theme: `dark`, `light` or `mono`. |
| `--json` | off | With `--stream`: one JSON object per event (JSONL). |

```bash
sentry tail --only High,Critical --theme mono
sentry tail --stream --json | jq 'select(.level == "critical")'
```


## IP

### `sentry ip`

Inspect or block/unblock an IP. The IP is positional and comes **before**
the subcommand; with no subcommand it defaults to `info`. Blocks publish
`sentry_blocks_changed` (daemon and edge enforce within seconds). Handler in
[`cmd.rs`](https://github.com/IDjinn/sentry/blob/main/crates/sentry-cli/src/cmd.rs).

| Subcommand | Description |
| --- | --- |
| `info` (default) | Block state, reason, expiry, strikes and total violations. |
| `block [--ttl <dur>] [--note <text>]` | Block (optionally with expiry). |
| `unblock` | Remove the block. |
| `forgive` | Reset the strike counters (offender memory); history is kept. |

```bash
sentry ip 203.0.113.7 info
sentry ip 203.0.113.7 block --ttl 24h --note "scanner"
sentry ip 203.0.113.7 forgive
```

## Routes

### `sentry routes`

Known routes (config ∪ database). Handler in
[`cmd.rs`](https://github.com/IDjinn/sentry/blob/main/crates/sentry-cli/src/cmd.rs);
importers in
[`routes_import.rs`](https://github.com/IDjinn/sentry/blob/main/crates/sentry-cli/src/routes_import.rs).

| Subcommand | Description |
| --- | --- |
| `list` | Lists database routes (or config routes when the DB is empty). |
| `learn [--dry-run] [--min-hits 10] [--min-ips 2]` | Infers stable route shapes from recent events and persists the new ones. |
| `import <path> [--format <fmt>] [--dry-run]` | Imports routes from OpenAPI/Swagger 2/3, Postman v2.1 or HAR. `--format`: `openapi`, `swagger`, `postman`, `har`, `auto` (default: auto-detect). |

```bash
sentry routes learn --min-hits 20 --min-ips 3
sentry routes import openapi.yaml --dry-run
```

## Auto-detection

### `sentry auto`

Detects frameworks/routes and generates `sentry.auto.toml` (known routes +
packs + suggested rules). Detection lives in the
[`sentry-auto`](https://github.com/IDjinn/sentry/blob/main/crates/sentry-auto)
crate; orchestration and the HTTP probe in
[`auto.rs`](https://github.com/IDjinn/sentry/blob/main/crates/sentry-cli/src/auto.rs).

- **With a path** (`sentry auto /var/www/app`): scans the project tree
  (bounded walk) and extracts routes for the **nginx**, **WordPress**,
  **Laravel**, **Next.js** and **Express** profiles.
- **Without a path**: runs everything on its own — reads server configs
  from disk (`/etc/nginx`, sites-enabled/conf.d) and **probes the local
  service** on ports 80/443 (robots.txt, sitemap.xml and ~60 common
  paths; a random sentinel path filters catch-all/SPA fallbacks).
- **Opt-in modules**: pass `--probe` and/or `--disk` to run just one;
  with no flags, both run.
- **Output**: a `METHODS | PATH` table + detected frameworks and the
  `sentry.auto.toml` written next to the resolved `sentry.toml`. **When
  nothing is found the command prints nothing** (exit 0) and writes no
  file.

The generated file is **cascade-loaded** automatically: on every config
load, `routes.known`, `rules.pack` and `rules.custom` from
`sentry.auto.toml` are appended with dedupe — whatever is in your
`sentry.toml` always wins (there is no `--merge`; the cascade replaces
that flag).

| Flag | Default | Description |
| --- | --- | --- |
| `[ROOT]` | (none) | Project root to scan; without it, probes the local service (80/443) + disk configs. |
| `--probe` | off | Opt-in: only the local HTTP probe. |
| `--disk` | off | Opt-in: only on-disk config detection. |
| `--profile <name>` | (auto) | Forces a profile (`wordpress`, `laravel`, `nextjs`, `express`, `nginx`), skipping detection. |
| `--deep` | off | Scans the whole tree with regex (not just canonical files). tree-sitter AST stays on the backlog. |
| `--dry-run` | off | Print only; does not write `sentry.auto.toml`. |
| `-v` / `-vv` | off | Verbosity: scanned tree and versions (`-v`); per-file/request detail (`-vv`). |

```bash
sentry auto                        # everything: disk + 80/443 probe
sentry auto /var/www/app --dry-run # just preview what would be detected
sentry auto --disk                 # zero traffic: reads configs from disk
sentry auto --profile wordpress    # force the profile and probe WP paths
```

## Rules engine

### `sentry rules`

CRUD for custom database rules + view of config packs. Changes publish
`sentry_rules_changed` (hot-reload, no restart). Handler in
[`cmd.rs`](https://github.com/IDjinn/sentry/blob/main/crates/sentry-cli/src/cmd.rs).

| Subcommand | Description |
| --- | --- |
| `list` | Database rules + packs declared in `[rules]` (name = mode). |
| `show <id>` | Details of one rule (match, action, priority, ttl, tags). |
| `add --name <name> --match <dsl> --action <action> [--priority 100]` | Creates/updates a custom rule (rules engine DSL). |
| `allow <ip> [--ttl <dur>] [--note <text>]` | Creates an allowlist rule for the IP (priority 1). |
| `block <ip> [--ttl <dur>] [--note <text>]` | Creates a blocklist rule for the IP. |
| `enable <id>` / `disable <id>` | Enable/disable a rule. |
| `delete <id>` | Removes a rule. |
| `packs` | Lists the built-in default packs and each one's effective mode. |
| `test [--path /] [--method GET] [--ip <ip>] [--ua <ua>]` | Simulates which rules would match that request shape. |

```bash
sentry rules add --name "block admin scan" \
  --match 'path starts_with "/admin" AND country = "RU"' --action block
sentry rules test --path /.env --ua "sqlmap/1.0" --ip 203.0.113.7
```

## Reputation feeds

### `sentry feeds`

Reputation feeds configured in `[[rules.feeds]]` (Tor, Spamhaus, FireHOL,
datasets…). Handler in
[`cmd.rs`](https://github.com/IDjinn/sentry/blob/main/crates/sentry-cli/src/cmd.rs).

| Subcommand | Description |
| --- | --- |
| `list` | Name, kind, tier, refresh and URL of each feed. |
| `refresh` | Fetches all feeds once and shows entry counts (no daemon needed). |
| `check <ip>` | Refreshes the feeds, then looks the IP up against them. |

```bash
sentry feeds check 203.0.113.7
```

## Datasets

### `sentry datasets`

DB-backed datasets (User-Agent, path or JA3 lists) that become
`dataset:<name>` synthetic rules and feed the dynamic prefilter. Handlers in
[`cmd.rs`](https://github.com/IDjinn/sentry/blob/main/crates/sentry-cli/src/cmd.rs)
and [`datasets.rs`](https://github.com/IDjinn/sentry/blob/main/crates/sentry-cli/src/datasets.rs).

| Subcommand | Description |
| --- | --- |
| `list` | Name, kind, entry count and enabled state. |
| `import <path> --kind <k> --name <name> [--action log] [--dry-run]` | Imports a list (file or http(s) URL), one entry per line, replacing any previous version of that name. `--kind`: `user_agent`, `path` or `ja3`; `--action`: `allow`, `block`, `challenge`, `rate_limit`, `log` (default) or `tag`. |
| `enable <name>` / `disable <name>` | Enable/disable without deleting (running daemons hot-reload via NOTIFY). |
| `delete <name>` | Deletes the dataset. |
| `fetch` | Re-fetches the `source_url` of every enabled dataset and shows the new counts. |

```bash
sentry datasets import bad-bots.txt --kind user_agent --name bad-bots --action block --dry-run
```

| --- | --- |

```bash
sentry bots check 66.249.66.1 --ua "Googlebot/2.1"
```

## Protocols

### `sentry protocol`

Validation and inspection of the protocol DSL schemas (F9). Handlers in

| Subcommand | Description |
| --- | --- |
| `validate [dir]` | Compiles every `*.protocol.yaml` in the directory and reports errors. Default: `[protocol] dir`. |

## OS service

### `sentry service`

Installs the daemon as a system service: systemd
(`/etc/systemd/system/sentry.service`), launchd
(`~/Library/LaunchAgents/com.sentry.daemon.plist`) or a real Windows Service
(SCM). The service runs `sentry run`. Handler in
[`service.rs`](https://github.com/IDjinn/sentry/blob/main/crates/sentry-cli/src/service.rs).

| Subcommand | Description |
| --- | --- |
| `install [--user <u>] [--workdir <dir>]` | Installs and starts (`--user` is systemd-only; secrets come from the environment). |
| `uninstall` | Stops and removes the service. |
| `status` | Install paths + best-effort live status. |

```bash
sentry service install --user sentry --workdir /etc/sentry
```

## Reports

### `sentry report`

Postgres aggregate report: events by level and verdict, top IPs and top
paths. Handler in
[`cmd.rs`](https://github.com/IDjinn/sentry/blob/main/crates/sentry-cli/src/cmd.rs).

| Flag | Default | Description |
| --- | --- | --- |
| `--from <dur>` | `24h` | Look-back window (e.g. `24h`, `7d`). |
| `--export <fmt>` | (text) | `json` or `csv` on stdout. |
| `--unknown-paths` | off | Top paths without a known route (`UnknownRoute`) — candidates for `[[routes.known]]`. |

```bash
sentry report --from 7d --export csv
sentry report --unknown-paths
```

### `sentry posture`

Web security posture (F11): part 1 is a config checklist (TLS, HTTP→HTTPS
redirect, posture enabled); part 2 aggregates the header advisories observed
on the protected site's responses (inline edge, shadow) with a remediation
hint per line. Handler in
[`cmd.rs`](https://github.com/IDjinn/sentry/blob/main/crates/sentry-cli/src/cmd.rs);
checks in
[`posture.rs`](https://github.com/IDjinn/sentry/blob/main/crates/sentry-core/src/posture.rs).

| Flag | Default | Description |
| --- | --- | --- |
| `--from <dur>` | `24h` | Look-back window for observed advisories. |

```bash
sentry posture --from 24h
```

## SIEM export

### `sentry export`

Exports raw events as CEF, LEEF 2.0 or JSON for SIEM consumption.
Serializers in
[`siem.rs`](https://github.com/IDjinn/sentry/blob/main/crates/sentry-cli/src/siem.rs).

| Flag | Default | Description |
| --- | --- | --- |
| `--from <dur>` | `24h` | Initial look-back window. |
| `--format <fmt>` | `cef` | `cef`, `leef` or `json`. |
| `--out <file>` | (stdout) | Write to a file instead of stdout. |
| `--follow` | off | Keep tailing new events after the initial window. |
| `--to <target>` | (—) | With `--follow`: forward via syslog to `udp://host:514` or `tcp://host:514`. |

```bash
sentry export --from 7d --format leef --out sentry.leef
sentry export --follow --to udp://siem.internal:514
```

## AI model

### `sentry model`

Lifecycle of the classic ONNX model. Handler in
[`cmd.rs`](https://github.com/IDjinn/sentry/blob/main/crates/sentry-cli/src/cmd.rs).

| Subcommand | Description |
| --- | --- |
| `status` | Provider, mode (`fork`/`inline`/`shadow`), trigger, threshold, loaded model (needs a build with `--features onnx` to actually load it). |
| `reload` | Publishes NOTIFY `sentry_model_changed` — the daemon hot-swaps the ONNX from disk (requires Postgres). |
| `export [--hours 720] [--out dataset.csv] [--synthetic] [--rows 4000] [--confirmed]` | Exports features as CSV (extracted by Rust — training/inference parity). `--synthetic` generates a seed dataset without Postgres; `--confirmed` uses incidents as the positive label. |

```bash
sentry model export --synthetic --rows 8000 --out seed.csv
python tools/train_model.py --csv seed.csv
sentry model reload
```

## Benchmarks

### `sentry bench`

Provider evaluation harness. Handler in
[`bench_llm.rs`](https://github.com/IDjinn/sentry/blob/main/crates/sentry-cli/src/bench_llm.rs).

| Subcommand | Description |
| --- | --- |
| `llm [--providers jev,mock] [--events <file>] [--format <log_format>] [--n 0] [--concurrency 4] [--out <file>]` | Compares classification providers (LLM / jev / mock) on latency, agreement with the heuristic pipeline, output quality and cost. `--events` accepts an nginx access.log or a `.jsonl` of events; `--n 0` = all. |


## Environment variables

Secrets never go into committed config — use the environment. Beyond the
table, every config key can be overridden through env with the `SENTRY_`
prefix and `__` nesting (e.g. `SENTRY_STORAGE__POSTGRES__URL`); the overlay
is implemented in
[`config.rs`](https://github.com/IDjinn/sentry/blob/main/crates/sentry-cli/src/config.rs).

| Variable | Used by | Read in |
| --- | --- | --- |
| `SENTRY_CONFIG` | Config path (equivalent to `--config`). | [`cli.rs`](https://github.com/IDjinn/sentry/blob/main/crates/sentry-cli/src/cli.rs) |
| `SENTRY_STORAGE__POSTGRES__URL` | Postgres URL. | [`config.rs`](https://github.com/IDjinn/sentry/blob/main/crates/sentry-cli/src/config.rs) |
| `SENTRY_CF_TOKEN` | Cloudflare API token (actions + CLI + TUI). | [`cmd.rs`](https://github.com/IDjinn/sentry/blob/main/crates/sentry-cli/src/cmd.rs), [`daemon.rs`](https://github.com/IDjinn/sentry/blob/main/crates/sentry-cli/src/daemon.rs) |
| `SENTRY_CF_ZONE` | Cloudflare zone id. | [`cmd.rs`](https://github.com/IDjinn/sentry/blob/main/crates/sentry-cli/src/cmd.rs) |
| `SENTRY_CF_ACCOUNT` | Account id override (derived from the zone when unset). | [`cmd.rs`](https://github.com/IDjinn/sentry/blob/main/crates/sentry-cli/src/cmd.rs), [`lists.rs`](https://github.com/IDjinn/sentry/blob/main/crates/sentry-action-cloudflare/src/lists.rs) |
| `SENTRY_LLM_KEY` | OpenRouter API key ([llm]). | [`daemon.rs`](https://github.com/IDjinn/sentry/blob/main/crates/sentry-cli/src/daemon.rs) |
| `SENTRY_JEV_KEY` | `jev` LLM provider key (fallbacks `TYPESAFE_API_KEY` / `JEV_API_KEY`). | [`jev.rs`](https://github.com/IDjinn/sentry/blob/main/crates/sentry-ai/src/llm/jev.rs) |
| `SENTRY_SESSION_SECRET` | Dashboard session HMAC key (`[server.auth] session_secret_env`). | [`config.rs` (core)](https://github.com/IDjinn/sentry/blob/main/crates/sentry-core/src/config.rs) |
| `SENTRY_WEBHOOK_SECRET` | Webhook payload HMAC (`[server] webhook_secret_env` and the `webhook` action). | [`config.rs` (core)](https://github.com/IDjinn/sentry/blob/main/crates/sentry-core/src/config.rs), [`daemon.rs`](https://github.com/IDjinn/sentry/blob/main/crates/sentry-cli/src/daemon.rs) |
| `SENTRY_EDGE_CHALLENGE_SECRET` | JS challenge PoW secret (required with `[edge.challenge] enabled`). | [`config.rs` (core)](https://github.com/IDjinn/sentry/blob/main/crates/sentry-core/src/config.rs) |
| `SENTRY_ABUSEIPDB_KEY` | AbuseIPDB (`[ip_lookup]` and the `report` action). | [`config.rs` (core)](https://github.com/IDjinn/sentry/blob/main/crates/sentry-core/src/config.rs) |
| `SENTRY_REPORTEDIP_KEY` | `report` action key (`reportedip` provider). | [`lib.rs` (report)](https://github.com/IDjinn/sentry/blob/main/crates/sentry-action-report/src/lib.rs) |
| `SENTRY_OPN_API_KEY` / `SENTRY_OPN_API_SECRET` | OPNsense REST credentials. | [`lib.rs` (opnsense)](https://github.com/IDjinn/sentry/blob/main/crates/sentry-action-opnsense/src/lib.rs) |
