# API — `sentry-storage`

[`sentry-storage`](https://github.com/IDjinn/sentry/blob/main/crates/sentry-storage/src/lib.rs#L1) é a persistência Postgres do Sentry: pool, migrations embutidas e repositórios tipados (events, incidents, ip_state, rules, routes, datasets) usados pelo daemon, pela CLI e pelo dashboard. Todas as queries usam `sqlx::query()` em runtime, então a crate compila sem um `DATABASE_URL` vivo. Declara `#![forbid(unsafe_code)]`.

## Pool — módulo `pool`

### PgPool

```rust
pub struct PgPool { /* sqlx::PgPool */ }
pub async fn connect(cfg: &PostgresConfig) -> Result<Self>;
pub fn connect_lazy(url: &str) -> Result<Self>;
pub async fn listen(&self, channel: &str) -> Result<sqlx::postgres::PgListener>;
pub async fn notify(&self, channel: &str) -> Result<()>;
```

[`PgPool`](https://github.com/IDjinn/sentry/blob/main/crates/sentry-storage/src/pool.rs#L9) respeita `max_connections` e `acquire_timeout_secs` do `[storage.postgres]`; [`connect_lazy`](https://github.com/IDjinn/sentry/blob/main/crates/sentry-storage/src/pool.rs#L34) adia a conexão (tooling/testes). [`listen`](https://github.com/IDjinn/sentry/blob/main/crates/sentry-storage/src/pool.rs#L52) usa uma conexão dedicada fora do pool — o LISTEN pode bloquear indefinidamente sem starvation. Erros ficam em [`StorageError`](https://github.com/IDjinn/sentry/blob/main/crates/sentry-storage/src/pool.rs#L76) (`Config`/`Connect`/`Query`/`Migrate`).

## Repositórios — módulo `repo`

### Repo

[`Repo`](https://github.com/IDjinn/sentry/blob/main/crates/sentry-storage/src/repo.rs#L22) carrega o pool e empresta os repos: [`events()`](https://github.com/IDjinn/sentry/blob/main/crates/sentry-storage/src/repo.rs#L38), [`incidents()`](https://github.com/IDjinn/sentry/blob/main/crates/sentry-storage/src/repo.rs#L45), [`ip_state()`](https://github.com/IDjinn/sentry/blob/main/crates/sentry-storage/src/repo.rs#L52), [`rules()`](https://github.com/IDjinn/sentry/blob/main/crates/sentry-storage/src/repo.rs#L59), [`routes()`](https://github.com/IDjinn/sentry/blob/main/crates/sentry-storage/src/repo.rs#L66), [`datasets()`](https://github.com/IDjinn/sentry/blob/main/crates/sentry-storage/src/repo.rs#L73). Todos os métodos de IP canonizam o endereço ([`Event::canonical_ip`](https://github.com/IDjinn/sentry/blob/main/crates/sentry-core/src/event.rs#L243)).

### EventRepo

Repositório da tabela `events` ([`EventRepo`](https://github.com/IDjinn/sentry/blob/main/crates/sentry-storage/src/repo.rs#L84)).

**Escrita e dedupe cross-node:**

```rust
pub async fn insert_with_hash(&self, evt: &Event, risk_score: u8, risk_level: RiskLevel,
    verdict: Verdict, signals: &serde_json::Value, payload_hash: Option<i64>, process_us: Option<u64>) -> Result<()>;
pub async fn insert_batch_with_hash(&self, rows: &[EventInsert]) -> Result<()>;
```

[`insert_with_hash`](https://github.com/IDjinn/sentry/blob/main/crates/sentry-storage/src/repo.rs#L223) faz INSERT condicional: quando `payload_hash` já foi persistido por um nó irmão na janela de dedupe (10 s), a linha é pulada — o LRU local não enxerga eventos de outros nós (F4.7). [`insert_batch_with_hash`](https://github.com/IDjinn/sentry/blob/main/crates/sentry-storage/src/repo.rs#L339) é a lane de persistência em lote do overload response (1 multi-INSERT por lote). [`EventInsert::from_event`](https://github.com/IDjinn/sentry/blob/main/crates/sentry-storage/src/repo.rs#L134) monta a linha; protocolo que falha ao serializar vira JSON `null` — lote não perde evento por um payload ruim.

### DatasetRepo

Repositório dos datasets DB-backed (F7.7, [`DatasetRepo`](https://github.com/IDjinn/sentry/blob/main/crates/sentry-storage/src/repo.rs#L1230)) — listas curadas `user_agent`/`path`/`ja3` que viram regras sintéticas `feed:<name>` e alimentam o prefilter dinâmico:

```rust
pub async fn upsert(&self, name: &str, kind: &str, source_url: Option<&str>,
    action: &str, entries: &[String]) -> Result<()>;
pub async fn list(&self) -> Result<Vec<DatasetRow>>;

```

[`upsert`](https://github.com/IDjinn/sentry/blob/main/crates/sentry-storage/src/repo.rs#L1257) substitui o dataset wholesale numa transação e dispara `pg_notify` no canal `sentry_datasets_changed` ([constante](https://github.com/IDjinn/sentry/blob/main/crates/sentry-storage/src/repo.rs#L1251)); `set_enabled` e `delete` notificam igual — todos os nós hot-reloadam sem restart.

## Dedupe e LISTEN/NOTIFY

O **dedupe cross-node** (F4.7) funciona assim: cada nó calcula o mesmo `payload_hash` que o LRU local usa (IP + método + path para HTTP, hash do raw caso contrário); o INSERT compara contra o índice parcial `events_payload_hash_ts` na janela de 10 s e pula duplicatas persistidas por irmãos. O índice é parcial (`WHERE payload_hash IS NOT NULL`) — eventos sem hash nunca pagam o lookup.

Canais de **hot-reload** por LISTEN/NOTIFY (produtores → tarefas LISTEN no daemon):

| Canal | Dispara |
| --- | --- |
| `sentry_rules_changed` | Recompila o ruleset ([daemon](https://github.com/IDjinn/sentry/blob/main/crates/sentry-cli/src/daemon.rs#L2781)) |
| `sentry_datasets_changed` | Reimporta datasets no pipeline e no prefilter ([daemon](https://github.com/IDjinn/sentry/blob/main/crates/sentry-cli/src/daemon.rs#L2863); emitido pelo `DatasetRepo`) |
| `sentry_blocks_changed` | Re-sincroniza a `BlockTable` entre nós ([daemon](https://github.com/IDjinn/sentry/blob/main/crates/sentry-cli/src/daemon.rs#L2904)) |
| `sentry_model_changed` | Troca o ONNX a quente ([daemon](https://github.com/IDjinn/sentry/blob/main/crates/sentry-cli/src/daemon.rs#L2961)) |

O productor typical é a CLI/dashboard: mutação no Postgres + `NOTIFY` via [`PgPool::notify`](https://github.com/IDjinn/sentry/blob/main/crates/sentry-storage/src/pool.rs#L64). A exceção é `sentry_datasets_changed`, emitido dentro do próprio [`DatasetRepo`](https://github.com/IDjinn/sentry/blob/main/crates/sentry-storage/src/repo.rs#L1230) na mesma transação da escrita.

## Notas de operação

- [`EventRepo::insert`](https://github.com/IDjinn/sentry/blob/main/crates/sentry-storage/src/repo.rs#L205) é o wrapper single-row sem dedupe (delega a `insert_with_hash` com `payload_hash = None`) — caminhos de baixo volume; o caminho quente do daemon usa a lane em lote.
- `Repo` é `Clone` barato (só o handle do pool); cada repo emprestado também. Não há estado por repo — a fonte de verdade vive no Postgres, e caches locais (`BlockTable`, ruleset) são sincronizados pelos canais acima.
- O módulo [`error`](https://github.com/IDjinn/sentry/blob/main/crates/sentry-storage/src/error.rs#L3) re-exporta `StorageError`/`Result` definidos em `pool.rs`; toda falha de query vira `StorageError::Query` com o erro do sqlx no texto.
