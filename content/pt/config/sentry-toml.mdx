O arquivo [`config/sentry.example.toml`](https://github.com/IDjinn/sentry/blob/main/config/sentry.example.toml) é o exemplo canônico pronto para copiar.

## Carregamento e overlay de ambiente

O arquivo é carregado com `figment`: o TOML é a base e **qualquer campo pode ser sobrescrito por variável de ambiente** no formato `SENTRY_<SEÇÃO>__<CHAVE>` (maiúsculas, `__` separa níveis de aninhamento). Segredos **nunca** vão no arquivo commitado — só em env.

| Variável | Sobrescreve / alimenta |
| --- | --- |
| `SENTRY_STORAGE__POSTGRES__URL` | `[storage.postgres] url` |
| `SENTRY_CF_TOKEN` | token da API Cloudflare (sources/actions CF) |
| `SENTRY_CF_ZONE` | zone ID da Cloudflare (action challenge) |
| `SENTRY_CF_ACCOUNT` | account ID da Cloudflare (IP Lists /64) |
| `SENTRY_LLM_KEY` | chave da API do provedor LLM |
| `SENTRY_ABUSEIPDB_KEY` | chave da AbuseIPDB (`[ip_lookup]`, action report, feeds) |
| `SENTRY_SESSION_SECRET` | chave HMAC das sessões do dashboard |
| `SENTRY_WEBHOOK_SECRET` | segredo de assinatura HMAC dos webhooks |
| `SENTRY_EDGE_CHALLENGE_SECRET` | segredo do PoW do challenge da edge |

## [`[core]`](https://github.com/IDjinn/sentry/blob/main/crates/sentry-core/src/config.rs#L106)

Runtime principal: buffers de filas e tuning do caminho quente de ingest. Sob sobrecarga a fila de actions enche primeiro — o Sentry descarta **actions**, nunca eventos.

| Campo | Tipo | Padrão | Descrição |
| --- | --- | --- | --- |
| `data_dir` | string (caminho) | `/var/lib/sentry` | Diretório de dados (arquivos MMDB, modelos, cache). |
| `channel_buffer` | inteiro | `4096` | Tamanho do buffer do canal de eventos entre sources e daemon. |
| `action_buffer` | inteiro | `4096` | Capacidade da fila de actions postergadas (workers de pós-processamento). |
| `action_workers` | inteiro | `1` | Workers paralelos que executam actions de rede. `1` preserva a ordem estrita das actions. |
| `persist_buffer` | inteiro | `2048` | Capacidade da fila de persistência em lote (um multi-INSERT por lote). |
| `dedupe_ttl_secs` | inteiro | `10` | Janela de dedupe de ingest: eventos idênticos (ip, method, path) dentro da janela caem fora antes do pipeline. |

```toml
[core]
data_dir = "/var/lib/sentry"
action_workers = 1
dedupe_ttl_secs = 10
```

## [`[overload]`](https://github.com/IDjinn/sentry/blob/main/crates/sentry-core/src/config.rs#L176)

Resposta a sobrecarga: pressão medida (ocupação de filas, latência de INSERT no Postgres) liga a degradação em tiers de **telemetria**. Detecção (pipeline) e contenção (block table, actions) nunca degradam.

| Campo | Tipo | Padrão | Descrição |
| --- | --- | --- | --- |
| `enabled` | bool | `true` | Liga a detecção de pressão e os tiers de degradação. |
| `queue_pressure` | float | `0.8` | Ocupação de fila (0.0–1.0) que liga a pressão. |
| `release_pressure` | float | `0.5` | Ocupação abaixo da qual a pressão desliga (histerese). |
| `release_secs` | inteiro | `30` | Segundos de alívio sustentado antes de limpar a pressão. |
| `pg_insert_budget_ms` | inteiro | `250` | EMA de latência de INSERT (ms) que liga a pressão sozinha. |
| `sample_keep` | float | `0.1` | Fração de eventos de baixa prioridade (Allow < High) mantida sob pressão — determinística por IP de origem. |
| `coalesce_benign` | bool | `true` | Colapsa requisições benignas repetidas (Allow, GET, sem sinais) por (ip, path). |
| `coalesce_window_secs` | inteiro | `60` | Janela de coalescência benigna: só o primeiro hit persiste. |
| `coalesce_cap` | inteiro | `4096` | Máximo de buckets (ip, path) rastreados; o mais antigo é evictado. |

| Campo | Tipo | Padrão | Descrição |
| --- | --- | --- | --- |
| `mode` | string | `passive` | `passive` lê logs/tráfego espelhado e age ex-post via actions; `inline` roda o reverse proxy da [`[edge]`](#edge) na frente do app e aplica vereditos antes da requisição chegar ao backend. |
| `instance_id` | string | *(hostname)* | Rótulo de instância para métricas em deployments multi-nó (gauge `sentry_instance_info`). Vazio = deriva do hostname. |

## [`[storage.postgres]`](https://github.com/IDjinn/sentry/blob/main/crates/sentry-core/src/config.rs#L274)

Conexão de persistência (Postgres via sqlx).

| Campo | Tipo | Padrão | Descrição |
| --- | --- | --- | --- |
| `url` | string | *(vazio)* | String de conexão `postgres://user:pass@host:port/db`. Prefira `SENTRY_STORAGE__POSTGRES__URL`. |
| `max_connections` | inteiro | `10` | Tamanho do pool de conexões. |
| `acquire_timeout_secs` | inteiro | `5` | Segundos esperando por uma conexão livre antes de falhar rápido (default do sqlx é 30). |

## [`[[source]]`](https://github.com/IDjinn/sentry/blob/main/crates/sentry-core/src/config.rs#L2063)

Fontes de eventos: cada entrada declara um plugin `type` e um mapa `options` próprio do plugin. Tipos implementados: `nginx`, `syslog`, `cloudflare` e `tcp` (tipo desconhecido é ignorado com um log).

**`type = "nginx"`** — tail de access.log do nginx com parser de `log_format` e resolução automática do IP real.

| Option | Tipo | Padrão | Descrição |
| --- | --- | --- | --- |
| `path` | string | `/var/log/nginx/access.log` | Caminho do arquivo de log. |
| `format` | string | formato *combined* | Mesma string do `log_format` do nginx. Tokens `$http_*` viram headers do evento (usáveis em regras DSL como `header.cf-connecting-ip`). |

```toml
[[source]]
type = "nginx"
[source.options]
path = "/var/log/nginx/access.log"
format = '$remote_addr - $remote_user [$time_local] "$request" $status $body_bytes_sent "$http_referer" "$http_user_agent"'
```

**`type = "syslog"`** — receptor RFC 5424 (fallback RFC 3164) para firewalls e equipamentos de rede; o endereço do peer vira o IP do cliente.

| Option | Tipo | Padrão | Descrição |
| --- | --- | --- | --- |
| `bind` | string | `0.0.0.0:5140` | Endereço de escuta (portas < 1024 exigem root). |
| `transport` | string | `udp` | `udp` \| `tcp` (TCP aceita framing newline e octet-counting RFC 6587). |

**`type = "cloudflare"`** — polling da Logs API da Cloudflare (NDJSON); requer plano Enterprise e token com permissão Logs:Read via env.

| Option | Tipo | Padrão | Descrição |
| --- | --- | --- | --- |
| `zone_id` | string | *(obrigatório)* | Zone ID da Cloudflare. |
| `token_env` | string | `SENTRY_CF_TOKEN` | Variável de ambiente com o API token. |
| `poll_secs` | inteiro | `30` | Intervalo entre polls. |
| `start` | string (RFC 3339) | *(agora)* | Cursor da primeira consulta. |
| `api_base` | string | `https://api.cloudflare.com/client/v4` | Base da API. |

**`type = "tcp"`** — captura passiva de pacotes com fingerprinting de SYN (masscan/zmap/nmap). Exige o build feature `pcap` e privilégios (Npcap no Windows, `CAP_NET_RAW` no Linux).

| Option | Tipo | Padrão | Descrição |
| --- | --- | --- | --- |
| `interface` | string | *(obrigatório)* | Interface de captura. |
| `ports` | string (CSV) | *(vazio = todas)* | Filtro de portas de destino, ex. `"80,443,8443"`. |
| `payload_cap` | inteiro | `8192` | Bytes reassemblados mantidos por flow. |
| `flow_cap` | inteiro | `65536` | Máximo de flows rastreados (eviction FIFO). |
| `channel_buffer` | inteiro | `1024` | Fila entre o loop de captura e o daemon (mínimo 64). |
| `syn_window_ms` | inteiro | `100` | Janela de coalescência de SYN por IP (`0` = off); a rajada vira 1 evento com `TcpData.syn_count`. |

## [`[routes]`](https://github.com/IDjinn/sentry/blob/main/crates/sentry-core/src/config.rs#L345)

Rotas que sua aplicação realmente serve. Requisições fora do conjunto (ou com método não permitido) geram o sinal `UnknownRoute`.

| Campo | Tipo | Padrão | Descrição |
| --- | --- | --- | --- |
| `known` | array de [`[[routes.known]]`](https://github.com/IDjinn/sentry/blob/main/crates/sentry-core/src/config.rs#L353) | `[]` | Cada entrada: `path` (exato ou glob `/api/*`) e `methods` (vazio = qualquer método). |

```toml
[[routes.known]]
path = "/api/users/*"
methods = ["GET", "POST", "PATCH", "DELETE"]
```

## [`[route_learner]`](https://github.com/IDjinn/sentry/blob/main/crates/sentry-core/src/config.rs#L1799)

Aprendizado contínuo de rotas: task em background que infere shapes de rota estáveis a partir de eventos recentes no Postgres e faz hot-reload delas. Requer storage Postgres.

| Campo | Tipo | Padrão | Descrição |
| --- | --- | --- | --- |
| `enabled` | bool | `false` | Liga o learner contínuo. |
| `interval_secs` | inteiro | `300` | Frequência de cada passada de aprendizado. |
| `window_secs` | inteiro | `3600` | Janela de look-back dos eventos. |
| `min_hits` | inteiro | `10` | Hits mínimos para um shape ser considerado estável. |
| `min_ips` | inteiro | `2` | Mínimo de IPs distintos que acessaram o shape. |

## [`[rules]`](https://github.com/IDjinn/sentry/blob/main/crates/sentry-core/src/config.rs#L1901)

Motor de regras: packs padrão, regras estáticas inline, feeds de reputação e presets.

### [`[[rules.pack]]`](https://github.com/IDjinn/sentry/blob/main/crates/sentry-core/src/config.rs#L1921)

Packs padrão do motor de regras.

| Campo | Tipo | Padrão | Descrição |
| --- | --- | --- | --- |
| `name` | string | — | Nome do pack (lista abaixo). |
| `mode` | string | `shadow` | `shadow` (só anota/loga) \| `enforce` (age) \| `off`. |
| `params` | tabela | `{}` | Parâmetros extras do pack (ex.: `countries`, `domains`), achatados como `<pack>__<param>`. |

Packs disponíveis: `vpn_proxy`, `tor`, `crawlers_bad`, `crawlers_good` (divide-se em `crawlers_good_verified` / `crawlers_good_unverified_ok` com o bot verification ativo), `sensitive_paths` (único em `enforce` por padrão), `empty_ua`, `http_anomaly`, `rate_scan`, `country_blocklist` (`params.countries`) e `host_allowlist` (`params.domains`).

```toml
[[rules.pack]]
name = "country_blocklist"
mode  = "off"
[rules.pack.params]
countries = ["RU", "CN"]
```

### [`[[rules.custom]]`](https://github.com/IDjinn/sentry/blob/main/crates/sentry-core/src/config.rs#L1948)

Regras estáticas inline (além das gerenciadas pelo DB).

| Campo | Tipo | Padrão | Descrição |
| --- | --- | --- | --- |
| `name` | string | — | Nome legível da regra. |
| `priority` | inteiro | `0` | Menor = avaliada primeiro. |
| `match` | string (DSL) | — | Expressão de match; parse falho derruba a carga da config. |
| `action` | string | — | `allow` \| `block` \| `challenge` \| `rate_limit` \| `log` \| `tag`. |
| `tags` | array de string | `[]` | Tags livres para agrupamento. |
| `log_level` | string | `info` | Verbosidade no console: `silent` \| `info` \| `warn` \| `error`. |

```toml
[[rules.custom]]
name = "allow internal monitoring"
priority = 1
match = 'ip=10.0.0.0/8'
action = "allow"
log_level = "silent"
```

### [`[[rules.feeds]]`](https://github.com/IDjinn/sentry/blob/main/crates/sentry-core/src/config.rs#L1969)

Feeds de reputação e datasets (listas uma-por-linha).

| Campo | Tipo | Padrão | Descrição |
| --- | --- | --- | --- |
| `name` | string | — | Nome da feed (prefixo da tag da regra sintética). |
| `url` | string | — | URL http/https (hosts loopback/privados são rejeitados — guarda SSRF). |
| `kind` | string | `ip` | [`ip`](https://github.com/IDjinn/sentry/blob/main/crates/sentry-core/src/config.rs#L2007) \| `user_agent` \| `path` \| `ja3` — listas uma-por-linha viram regra sintética. |
| `refresh_hours` | inteiro | `24` | Intervalo de refresh em horas. |
| `tier` | string | `malicious` | `unknown` \| `clean` \| `suspicious` \| `malicious` \| `datacenter` \| `vpn` \| `tor` \| `authorized` \| `promiscuous` (só para `kind = "ip"`). |
| `action` | string | *(vazio)* | Para `ip`: vazio = só enriquecimento; para `user_agent`/`path`: vazio = `log`. Valores: `block` \| `challenge` \| `rate_limit` \| … |
| `enabled` | bool | `true` | Pausa a feed sem removê-la. |
| `headers_env` | tabela | `{}` | Mapa header → env var para feeds autenticadas (ex.: `Key = "SENTRY_ABUSEIPDB_KEY"`). |

```toml
[[rules.feeds]]
name = "spamhaus_drop"
url  = "https://www.spamhaus.org/drop/drop.txt"
tier = "malicious"
refresh_hours = 24
action = "block"
```

Datasets DB-backed (o equivalente Postgres das feeds `user_agent`/`path`/`ja3`) não têm entrada TOML — gerencie via `sentry datasets import | list | enable | disable | delete | fetch`.

### `feed_presets`

Presets de feeds embutidos, expandidos em `feeds` na carga.

| Campo | Tipo | Padrão | Descrição |
| --- | --- | --- | --- |
| `feed_presets` | array de string | `[]` | Nomes válidos: `tor_exit`, `firehol_level1`, `proxy_list`, `open_source_vpn_ips`, `anti_vpn`. Feeds de preset **bloqueiam** por padrão; uma feed manual com o mesmo nome vence. |

## [`[policy]`](https://github.com/IDjinn/sentry/blob/main/crates/sentry-core/src/config.rs#L395)

Política de vereditos: mapeia nível de risco → veredito. Sobrescritas ordenadas via [`[[policy.override]]`](https://github.com/IDjinn/sentry/blob/main/crates/sentry-core/src/config.rs#L431): a primeira expressão DSL que casar força o veredito.

| Campo | Tipo | Padrão | Descrição |
| --- | --- | --- | --- |
| `info` | string | `allow` | Veredito para eventos Info. |
| `low` | string | `allow` | Veredito para eventos Low. |
| `medium` | string | `rate_limit` | Veredito para eventos Medium. |
| `high` | string | `challenge` | Veredito para eventos High. |
| `critical` | string | `block` | Veredito para eventos Critical. |
| `override` | array | `[]` | Cada entrada: `match` (DSL) e `verdict` (`allow` \| `rate_limit` \| `challenge` \| `block` \| `quarantine`). |

```toml
[[policy.override]]
match = 'path ^/wp-admin$ AND NOT ip=10.0.0.0/8'
verdict = "block"
```

## [`[escalation]`](https://github.com/IDjinn/sentry/blob/main/crates/sentry-core/src/config.rs#L458)

Escalonamento de reincidentes: todo evento com veredito não-Allow registra 1 strike para o IP. Strikes só sobem o veredito, nunca baixam, e a janela deve sobreviver ao TTL da action de edge (o reincidente volta do TTL já re-bloqueado no primeiro evento violador).

| Campo | Tipo | Padrão | Descrição |
| --- | --- | --- | --- |
| `enabled` | bool | `true` | Liga o escalonamento por strikes. |
| `window_secs` | inteiro | `604800` | Strikes expiram N segundos após a última violação (7 dias, maior que o TTL típico de 24h da edge). |
| `challenge_at` | inteiro | `3` | Strikes para escalar para pelo menos `challenge`. |
| `block_at` | inteiro | `5` | Strikes para escalar para `block`. |
| `persist` | bool | `true` | Espelha strikes na tabela `ip_state` (Postgres) e pré-aquece o tracker no startup. |

## [`[scan]`](https://github.com/IDjinn/sentry/blob/main/crates/sentry-core/src/config.rs#L507)

Detecção comportamental de varreduras: janela deslizante por IP contando respostas 4xx — caminhos 4xx distintos → sinal `RandomScan`; total de 4xx → sinal `ScanBehavior`.

| Campo | Tipo | Padrão | Descrição |
| --- | --- | --- | --- |
| `enabled` | bool | `true` | Liga os trackers de scan. |
| `window_secs` | inteiro | `60` | Duração da janela deslizante. |
| `distinct_paths` | inteiro | `8` | Caminhos 4xx distintos por IP que disparam `RandomScan`. |
| `not_found` | inteiro | `10` | Total de 4xx por IP que dispara `ScanBehavior`. |

## [`[behavior]`](https://github.com/IDjinn/sentry/blob/main/crates/sentry-core/src/config.rs#L1136)

Detecção comportamental de ataques de autenticação e diretório por janela deslizante por IP.

| Campo | Tipo | Padrão | Descrição |
| --- | --- | --- | --- |
| `enabled` | bool | `true` | Liga os trackers de comportamento. |
| `window_secs` | inteiro | `300` | Janela deslizante por IP. |
| `auth_failures` | inteiro | `10` | Falhas 401/403 em rotas de login que disparam `AuthBruteForce`. |
| `distinct_uas` | inteiro | `3` | User-Agents distintos falhando auth que disparam `CredentialStuffing`. |
| `wordlist_hits` | inteiro | `5` | 404s em paths de wordlist que disparam `DirectoryBruteForce` (bons crawlers são isentos). |
| `suspicious_success_min_failures` | inteiro | `3` | Falhas de auth que precisam preceder um 2xx em rota de login para disparar `SuspiciousLoginSuccess` (`0` desliga). |
| `login_patterns` | array de string | `[]` | Substrings que identificam rotas de autenticação (vazio = lista embutida). |
| `wordlist_paths` | array de string | `[]` | Paths conhecidos de probe (vazio = wordlist embutida). |

## [`[correlation]`](https://github.com/IDjinn/sentry/blob/main/crates/sentry-core/src/config.rs#L548)

Correlação scan→ataque cross-IP ("shot calling" entre nós observando a mesma superfície): um ataque do IP B correlaciona com um scan de um IP **diferente** no mesmo /24 (IPv4), /64 (IPv6) ou ASN observado na janela → sinal `ScanAttackCorrelation` em B.

| Campo | Tipo | Padrão | Descrição |
| --- | --- | --- | --- |
| `enabled` | bool | `true` | Liga o tracker de correlação. |
| `window_secs` | inteiro | `900` | Idade máxima do scan para correlacionar (15 minutos). |

## [`[rate_limit]`](https://github.com/IDjinn/sentry/blob/main/crates/sentry-core/src/config.rs#L1283)

Backend de rate-limit para condições DSL de rate (`RuleMatch::Rate`).

| Campo | Tipo | Padrão | Descrição |
| --- | --- | --- | --- |
| `backend` | string | `memory` | `memory` (janela deslizante em processo, single-node) \| `redis` (multi-nó; exige o build feature `rate-redis`). |
| `redis_url` | string | `redis://127.0.0.1/` | URL do Redis (usada só com `backend = "redis"`). |

## [`[real_ip]`](https://github.com/IDjinn/sentry/blob/main/crates/sentry-core/src/config.rs#L626)

Resolução do IP real do cliente, proxies confiáveis e conjuntos never-ban/never-allow.

| Campo | Tipo | Padrão | Descrição |
| --- | --- | --- | --- |
| `trusted_proxies` | array de string | `[]` | CIDRs/IPs de peers autorizados a setar headers de client IP (`CF-Connecting-IP`, `True-Client-IP`, `X-Real-IP`, XFF). Headers de outros peers são ignorados (anti-spoof). |
| `cloudflare` | bool | `true` | Inclui as faixas Cloudflare embutidas (refresh diário de cloudflare.com/ips). |
| `trusted_ips` | array de string | `[]` | Clientes nunca banidos/bloqueados/reportados (admins, uptime probes) — short-circuit do pipeline para `Allow`. |
| `trusted_lists` | array de string | `[]` | Presets embutidos aprovados por nome (ex.: `paypal`, `stripe`, `googlebot`, `bingbot`) — entram no conjunto never-ban. |
| `whitelist` | array de string | `[]` | Permite tudo, nunca bane — mesclado no mesmo conjunto never-ban. |
| `blacklist` | array de string | `[]` | Nega imediatamente — o pipeline short-circuita para `Block` antes de qualquer detector. |

| --- | --- | --- |
| `key_env` | default do provider (ex.: `SENTRY_ABUSEIPDB_KEY`) | Env com a chave da API; chave ausente pula a action com warning. |
| `min_verdict` | `block` | Veredito mínimo reportado: `block` \| `challenge` \| `rate_limit`. |
| `dedupe_hours` | `24` | Um report por IP por janela. |
| `timeout_secs` | `10` | Timeout por requisição. |

**`type = "webhook"`** — POST JSON de alerta (Discord recebe embed rico automaticamente).

| Option | Padrão | Descrição |
| --- | --- | --- |
| `url` / `url_env` | — (um dos dois é obrigatório) | URL do webhook; prefira `url_env` (a URL é credencial). `url_env` vazio pula a action com warning. |
| `on_levels` | `["high", "critical"]` | Níveis de risco que disparam o POST. |
| `timeout_secs` | `10` | Timeout do POST. |
| `secret_env` | `SENTRY_WEBHOOK_SECRET` | Quando a env existe, requisições são assinadas com `X-Sentry-Signature: sha256=<hmac>` e o payload carrega `incident_id`/`ack_url` para callback. |

**`type = "log"`** — embutida, emite linha de tracing no act.

## Validação e segredos

```bash
sentry config validate   # valida schema, regras DSL e schemas de protocolo
sentry config show       # imprime a config resolvida (com overlay aplicado)
```

`sentry config validate` compila as regras custom (a DSL é parseada na carga), compila os schemas de protocolo quando `[protocol] enabled`, **rejeita** `[posture] mode = "enforce"` (ainda roadmap), avisa sobre ids desconhecidos em `[posture] checks` e imprime os advisories de topologia/performance da edge (TLS duplo, upstream http fora do loopback, compressão inerte fora do inline).

Regras de segurança:

- Segredos (tokens Cloudflare/LLM/DB, chaves de API, segredos de sessão) **nunca** em config commitada — via env (`SENTRY_*`).
- `sentry.example.toml` tem placeholders, não valores reais.
- O pack `sensitive_paths` bloqueia `.env`, `.git/`, `.ssh/`, etc. por padrão — ao expor uma rota allowlistada, justifique no PR.
