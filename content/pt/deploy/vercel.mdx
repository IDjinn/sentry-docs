# Deploy da Documentação na Vercel

A documentação do Sentry é um app **Fumadocs** (Next.js 16 + MDX + Tailwind v4
+ Mermaid) separado do binário Rust, morando no submodule git `docs/` e
deployado na **Vercel** em **sentry.lucas-romero.com**.

## Por que separado

- O binário Rust é o produto; a docs é um site Next.js.
- Fumadocs roda em Node.js (Next.js), não em Rust.
- A Vercel oferece edge CDN, preview deployments e otimização automática
  para Next.js.

## Estrutura do app de docs

```
docs/
├── content/
│   ├── pt/                  # conteúdo MDX (PT-BR, primário)
│   └── en/                  # conteúdo MDX (inglês, tradução)
├── src/
│   ├── app/[lang]/          # home + rotas de docs (i18n: pt, en)
│   │   └── docs/[[...slug]]/
│   ├── components/          # mermaid.tsx, mdx.tsx
│   └── lib/                 # source.ts (loader), i18n.ts, layout.shared.tsx
├── source.config.ts         # config Fumadocs MDX
├── next.config.mjs
├── vercel.json
└── package.json             # scripts com bun
```

O loader (`src/lib/source.ts`) registra `baseUrl: '/docs'` com i18n de
directório (`content/<lang>/`), e o i18n define `pt` como linguagem default —
as rotas públicas são `/pt/docs/...` e `/en/docs/...`.

## vercel.json

O [`vercel.json`](https://github.com/IDjinn/sentry/blob/main/docs/vercel.json)
configura, além do app:

- **Redirect** `/` → `/pt` (temporário — raiz cai na linguagem default).
- **Security headers** em todas as rotas: `X-Content-Type-Options: nosniff`,
  `X-Frame-Options: SAMEORIGIN`,
  `Referrer-Policy: strict-origin-when-cross-origin`.
- **Cache imutável** para `/_next/static/*`
  (`max-age=31536000, immutable`).

## Deploy na Vercel

1. Importe o repositório `sentry-docs` na Vercel.
2. Framework preset: **Next.js**.
3. Build command: `next build` (default).
4. Output: `.next` (default).
5. Variáveis de ambiente: nenhuma necessária (conteúdo é estático).
6. Domínio custom: `sentry.lucas-romero.com`.

## i18n

O app suporta `pt` (default) e `en`. As rotas são `/<lang>/docs/...` e o
conteúdo vive em `content/pt/` e `content/en/` — cada página precisa existir
nas duas linguagens com a mesma estrutura (títulos, tabelas e code fences
idênticos; só a prosa e o frontmatter são traduzidos).

## Mermaid

Os diagramas Mermaid são renderizados client-side via `mermaid.tsx`
(componente `<Mermaid chart={...} />`). O componente carrega `mermaid`
dinamicamente (`await import('mermaid')`) para não inflar o bundle inicial.
